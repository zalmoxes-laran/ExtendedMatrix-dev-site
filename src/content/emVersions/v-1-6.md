## Summary

Major architectural turning point: the **RDF triplestore becomes the persistent source of truth** for EM data, with the in-memory property graph treated as an editing cache. This unblocks (a) SPARQL queries as a daily-workflow capability, (b) multi-tool concurrent read/write to the same dataset, (c) formal HDT-O integration as per ECHOES Deliverable D7.1.

## RDF & HDT-O integration (game-changer for the EM ecosystem)

### Ontology layer

- **`em.ttl`** — first formal Extended Matrix ontology (~30 classes, 13 properties, 245 triples). Declares the `em:` namespace covering authors (HumanAuthor, AIAuthor), virtual SUs (VirtualSU + 4 specializations), real SUs (NegativeSU, ReusedSpecialFind, DisplacedSpecialFind), series, stratigraphic events, TimeBranch, RepresentationModel + specializations, SemanticShape, Rights (License, Embargo, EMGraph), Qualia (paradata shell), Paradata head, and AP11 subproperties (abuts, cuts, fills, overlies, bondedTo, physicallyEquals) as the SPARQL-friendly discrimination pattern.
- **`hdto_extension.ttl`** — minimal HDT-O subset aligned with ECHOES D7.1 ("The Digital Commons"). 5 classes (HC1 Heritage Entity, HC2 Heritage Digital Twin ⊂ HC14, HC14 Volatile, HC15 Persistent, HC16 Heritage Proposition Set ⊂ HC15), 7 properties (HP1 has digital twin, HP3 is digital twin component of with transitive closure, HP29 has digital object part, HP33 contains + inverses). Companion file declaring the HDT-O subset s3dgraphy needs, with scope notes citing D7.1 §4. Will be reconciled with the official IRI when the ECHOES consortium publishes it.

### Datamodel & exporter

- **Node datamodel v1.6.0**: systematic CIDOC-CRM mapping revision; legacy pseudo-class `cidoc_s3d` strings replaced with formal `em:` IRIs; 29 of 41 node classes carry `em_extension` blocks.
- **AuthorNode** split into AuthorNode (human, em:HumanAuthor) and AuthorAINode (em:AIAuthor) — the latter was already referenced in `has_author` edge targets but had no formal declaration.
- **HDTNode** — new node type for explicit HDT hierarchies inside an EM graph. Hierarchically composable via `has_digital_twin_component` (HP3 inverse, transitive); EMGraph→HDT attachment via `contains_proposition_set` (HP33).
- **Connections datamodel v1.6.0**: typo fix (`ProperrtyNOde` → `PropertyNode`); semantic fix on `has_documentation` (P104 → P70i_is_documented_in); deprecation of `has_timebranch` (canonical is `is_in_timebranch`); +4 HDT-O containment edges.
- **CRMinf** promoted to primary mapping for the paradata chain: ParadataNode (I1_Argumentation), ExtractorNode (I7_Belief_Adoption), CombinerNode (I5_Inference_Making).
- **Semantic corrections** for Virtual SUs (now `crminf:I4_Proposition_Set` not `crmarchaeo:A2` physical), NegativeSU (A3 Interface), DocumentaryVirtualSU (no longer confused with E31 Document).
- **RDFExporter** (`s3dgraphy.exporter.rdf_exporter`) — Turtle / N-Triples / N-Quads / TriG / JSON-LD / RDF-XML. Multi-typing via subclass_of; conditional PropertyNode mapping (qualia type drives CRM class — height→E54, aesthetic_value→I4, etc.); AP11 subproperty discrimination; named-graph wrapping; deprecated-edge skip; parent HDT binding via HP33i.

### Qualia v4.0

- Expanded from ~30 to ~80 qualia. New subcategories: **iconographic** (subject, narrative, program), **semantic** (aesthetic_value — the "bello/brutto" interpretive axis, religious_significance, monumental_status, attribution), **ownership** (custodian, ownership chain).
- **NEW CATEGORY epistemic** — meta-qualia central to the EM paradata model: confidence_level, certainty_level, uncertainty_factors, methodology_used, validation_method, source_quality, primary_contributor, review_status, last_modified. This is the formal machine-readable expression of EM's reasoning chain.

### EM-blender-tools integration

- **RDF Export panel** in the EM Bridge sidebar (provider pattern, parallel to Heriverse export). Format dropdown, output path, base URI, parent HDT IRI, all-publishable toggle, info on the Oxigraph/YasGUI workflow.

### Architectural implications

- HC14 Volatile vs HC15 Persistent in D7.1 is a **lifecycle distinction**, not a storage-format one. The triplestore can host both: HDTs (HC2 ⊂ HC14) evolve over time by swapping proposition sets (HC16 ⊂ HC15) via HC11 Digital Twin Maintenance activities. v1.6.0 ships the export side; v1.6.2/1.6.3/1.6.4 will add the read, write, and lifecycle pieces respectively.
- Deployment topologies are now multi-headed: centralized Virtuoso (office, internet), hyperlocal Oxigraph (rover/field, no internet), pyoxigraph embedded (single user, zero servers), hybrid sync (field + office). See s3dgraphy roadmap for details.
